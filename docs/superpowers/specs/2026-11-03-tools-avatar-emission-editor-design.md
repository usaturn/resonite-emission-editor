## 目的

Resonite 内で、事前に登録したアバターが使用するマテリアルの `EmissionColor` を確認し、入力した RGB をリアルタイムに反映して見た目を確認できる、持ち運べる UIX パネルを作る。元の値を保持し、「元に戻す」とキャンセルで復元し、OK で変更を確定する。任意のアバターを登録可能にし、今回の2体の名前に依存させない。登録だけは PC 側から ResoLoop を使い、通常の利用中に補助プロセスを必要としない。

発光が強いだけでは設定異常と断定しない。正常な見本の値を自動推定したり、一定値以上を自動で暗くしたりしない。

## 利用者が選択した仕様

1. 今回の Plum 専用ではなく、任意のアバターを登録できる汎用ツール。
2. 対象の指定方法は、ワールド内の登録済みアバター一覧からの選択と、登録済みアバターのルートのドラッグ＆ドロップの両方。未登録のルートは再登録を案内する。
3. どのメッシュの値をどう変えているかを、元の値と変更後の値の一覧で確認できる。
4. 「変更後」は現在値で初期化し、必要な行だけ利用者が手動で編集する。
5. 有効な入力はアバターへリアルタイムで反映する。「元に戻す」は編集開始時の値へ戻して編集を継続し、OK はプレビューを確定して終了、キャンセルは編集開始時の値へ戻して終了する。
6. 同じマテリアルを共有するメッシュは1行へまとめ、影響するメッシュをすべて表示して一緒に変更する。メッシュごとの分離・マテリアルの複製は行わない。
7. UI はスマートな見た目にする。具体的な色・寸法・余白は実装担当の提案。

## 検討した方式と採用理由

| 方式 | 利点 | 制約 | 判断 |
| --- | --- | --- | --- |
| 手動編集する一覧・ライブ反映・復元 | 実際の見た目を見ながら調整でき、元へ戻せる | 変更前の値と最後の書き込みを保持する必要がある | 利用者が採用。旧一括反映方式から変更 |
| 上限を指定した一括抑制 | 多数の材質をまとめて処理できる | 意図した強い発光も候補になる | 採用しない |
| 正常な見本からコピー | 同じ構成なら元の色を再現できる | 正常な見本と対応付けが必要 | 採用しない |

対象の選択は、一覧とドラッグ＆ドロップを併用する。共有マテリアルはまとめて編集し、メッシュごとの複製方式は採用しない。

## UI の提案

独立して持ち運べる平面パネルとする。仮称は「Emission Editor」。チャコールの背景、淡い文字、シアンのアクセント、控えめな枠と余白で構成する。装飾自体を強く発光させない。

上部に対象名と「登録済みアバター」「値を再読込」、ルートを受け取るドロップ領域を置く。同名アバターは名前に加えて親の経路と登録時のワールド内の位置を表示し、選択後も対象を判別できるようにする。同名で経路も同じ場合は一覧内の識別表示を追加する。名前を対象の内部識別キーには使わない。「ライブ反映中」「登録時の共有先」「構成変更後は再登録が必要」を読める形で示す。「値を再読込」は新しい材質の登録とは区別する。プレビュー中に元の値を取り直して復元先を失わないよう、変更が残っていれば先に確定または取消を求める。

中央に、ヘッダーを固定したスクロール可能な一覧を置く。行の単位はマテリアルの実体である。

| 影響するメッシュ | マテリアル | 編集開始前の RGB | 変更後の R / G / B | 状態 |
| --- | --- | --- | --- | --- |
| Dress1 / Dress2 / Dress3 | Dress_c1 | 48.906 / 18.754 / 8.997 | [48.905663] [18.754316] [8.996798] | 未変更 |
| Ruffle / Sleeve | Sleeve_c1 | 8.736 / 14.338 / 18.707 | [8.73594] [14.337809] [18.707266] | 未変更 |
| Shoe | Shoe_c1 | 1.279 / 15.484 / 271.174 | [1.2791259] [15.484132] [271.17404] | 未変更 |

これは画面構成案であり、入力欄に表示する値は読み取った現在値である。上表の値を汎用の初期値に固定しない。表示用の丸めを保存値へ戻さず、未編集行の精度を保つ。長いメッシュ一覧は行内を展開してすべて読めるようにする。

既定の編集項目は RGB の3つ。Alpha と色プロファイルは読み取り表示して保持する。RGB は HDR の 1 を超える値を編集可能とし、0..1 に自動で切り詰めない。入力の途中で空欄・不正値があれば、その行を示して「OK」を無効にする。NaN と無限大は受け付けない。負の RGB は発光の調整値として受け付けない。観測時から負値だった場合も勝手に補正しない。

有効な RGB 入力で対象を更新し、反映済みの行をアクセントで示す。不正な入力の途中では最後の有効なプレビュー値を保ち、0 や元値を勝手に書かない。下部には「プレビュー N 件」「元に戻す」「キャンセル」「OK」を置く。「元に戻す」は編集開始前の完全な色を復元し、入力欄も戻して編集を続けられる。「OK」は現在のプレビューを確認して確定し、編集を終える。入力が不正・競合・書き込み失敗のままでは確定しない。「キャンセル」は復元成功後に編集を終える。復元の失敗や競合は行ごとに示し、元に戻ったと誤報告せず、復元記録を残す。不正入力でも復元操作は使えるようにする。

選択を切り替える前にプレビューがあれば、確定・元へ戻して切替・編集を継続の選択を出す。別アバターへ元値やプレビューを移さない。復元が不完全なまま別の編集を開始して記録を消さない。

## 読み取りと共有マテリアル

登録時に、現在のワールドから AvatarRoot を持つ対象ルートを検証し、同じ Slot の重複を除く。登録処理は明示したルートだけを登録し、Root、ユーザールート、ツール自身、破棄された参照、アバターのルートでない対象を拒否する。パネル内の一覧はその登録データから作る。ドロップは登録したルートの参照との一致で判定し、名前の一致や古い生 ID で代用しない。

PC 側の登録処理が、対象アバター内の MeshRenderer / SkinnedMeshRenderer の材質参照から、実際に使われている EmissionColor を列挙する。名前や材質の格納場所だけで探さず、同じマテリアル参照を1行にまとめる。表示対象は実行環境で確認できた、公開の `EmissionColor` を持つ `colorX` のマテリアル。XiexeToonMaterial を初回の検証対象に含める。違う型や未対応の材質は理由を表示し、推測して別のフィールドを書き換えない。

共有マテリアルの変更は、選択アバター以外にも影響し得る。登録時にワールドのメッシュ参照を読み取り、その時点の全共有先を一覧へ登録する。アバター外の共有先は区別して示す。外部共有先がある行は、展開して影響先を明示的に確認するまで入力によるプレビューを無効にする。内部共有だけの行には追加の確認操作を設けない。

ワールドの走査は登録時だけ行い、毎フレームの走査や書き込みは行わない。大きなワールドでは分割して進捗を表示する。上限・中断・権限不足で登録が不完全なら、その旨を示し、該当行を反映可能とは扱わない。上限の具体値は実装計画で決める。登録によってアバターの Component・値・名前・構成を変更せず、パネル内へ検証済みの参照と表示情報だけを作る。

登録後に増えた Renderer、別のメッシュに新たに設定された共有材、新しい材質などは、単独パネルから自動発見できない。構成を変更した場合や別のワールドへ持ち込んだ場合は再登録する。登録済み参照の変更・消失は検査するが、新しい共有先が一切ないことの動的な保証はしない。共有先の表示は登録時点の情報であると明記し、現在のワールド全体を再走査した結果と表示しない。

## ライブ反映・確定・復元

編集開始時に対象参照、材質参照、利用先と完全な元の colorX を保存する。元値はこの編集セッションの間は固定する。別に、入力文字列、計算したプレビュー色、ツールが最後に書き込んで読み戻した値、プレビューした行の集合を保持する。再読込や連続入力で元値を上書きしない。

プレビューは3つの RGB がすべて有効になった時点で、同じ材質につき1回の色の書き込みとして行う。入力中の短い待ち時間で連続入力をまとめてもよいが、毎フレーム書き続けたり対象へ Drive したりしない。待機中のプレビューには編集と入力の世代を結び、元に戻す・キャンセル・選択変更・編集終了で古い処理を無効にする。復元後に古い入力が再反映されてはならない。書き込む前に、操作者と選択・登録世代、登録済みルート・フィールド・Renderer の既知の参照、共有先の確認状態を検証する。現在値は「ツールが最後に反映した値」と比較し、最初の書き込みだけ元値と比較する。違いがあれば外部変更としてプレビューを止める。書き込み後の値を読み戻すまで成功にしない。

OK は最後に入力した有効なプレビューが未処理ならその完了を待ち、各行の入力・参照・現在値を再確認する。すべて正常ならその状態を確定して復元記録を閉じる。適用済みの色を OK 自体で再送する必要はない。次の編集開始時に、確定後の値を新しい元値として保存する。

「元に戻す」とキャンセルは、実際にプレビューした行だけを対象にする。復元前にも現在値と最後の反映値を比較し、別の利用者やロジックの変更を上書きしない。完全な元の colorX を戻して読み戻し、成功した行の入力欄と反映値を更新する。外部変更や書き込み拒否で戻せない行は失敗として記録し、復元記録を消さない。キャンセルは全対象を復元できたときに編集を終了し、部分失敗なら復元未完了と表示する。

変更するのは EmissionColor だけで、ほかの色、テクスチャ、シェーダー、メッシュ、スケール、アバターのロジックは変更しない。駆動を切り離して書き込みを強制しない。途中失敗は成功分と失敗分を分けて報告し、未確認の全件成功や一括ロールバックを約束しない。Resonite の書き込みに他ユーザーとの不可分な競合防止があるとは扱わない。

パネルを共有して使う場合、編集セッションは1人の操作者が持つ。別の利用者は使用中の表示を読み取れるが、同時編集や代理のプレビュー・OK はできない。操作者の退出時は、共有の復元記録から同じ競合検査付きで取り消す。書き込み担当はホストなど1人に明示し、復元不能なら記録を保持して復元未完了を表示する。操作者の取得時は同期状態を読み戻して確認し、厳密な同時取得防止を証明できなければ、その検証限界を報告する。

## 実装の構成

通常の利用時に PC 側の Python や ResoniteLink の常駐処理を必要としない、Resonite 内で動作するパネルを作る。

- UIX のレイアウト、入力、スクロール、ドロップは、実行環境で確認したネイティブ Component を使う。
- PC 側の Python 登録処理が、ResoLoop でアバター・メッシュ・材質を読み取り、パネル内の登録情報と検証済みの参照を作る。単独のパネルは、登録済みの参照に対する読み書き、ライブ反映・確定・復元、結果の処理をネイティブ Component と ProtoFlux で行う。新しい Component の動的検索は行わない。
- ProtoFlux は `.pg` から Flux-SDK で生成する。ノードの直接生成や、未検証の内部 API への書き込みは行わない。
- 参照と編集状態の寿命を明示する。未確定のプレビューが残る間は元値と最後の反映値、対象参照を復元記録として保持し、再適用・再配置・ワールドの再起動で勝手に消さない。起動時に復元待ちの記録があれば、ホストだけが競合検査付きで復元してから編集を許可する。ゲストの参加ではリセットや復元を繰り返さない。保存・移動前には OK またはキャンセルで編集を終えるよう案内する。同じ保存済みワールド内では登録参照が有効なら再選択できる。別ワールドや複製では再登録が必要で、生 ID で復元しない。
- UI、リソース、テンプレート、実行ロジックはパネルの ObjectRoot 配下へ収める。登録済み対象への参照は意図した外部参照として明示する。このため、登録を含むパネルを単体で保存して別ワールドへ持ち込めばそのまま使えるとは保証しない。配布用の未登録パネルは登録を解除し、外部参照が残っていないことを監査する。
- 宣言は `content/emission-editor/`、ProtoGraph は `flux/emission-editor/`、生成支援は `scripts/`、検証は `tests/`、証拠は `artifacts/` に置く。所有キーは `tools-emission-editor`、所有ルート名は `ResoLoop_Test_EmissionEditor` とする。現在の検証先では新しい `.resoloop/state/emission-editor-19652.json` を使い、旧 `32423` の `.resoloop/state/emission-editor.json` は保持する。Flux の deploy state も新旧で分ける。ファイル名のポート番号は識別用で、ワールドの同一性の証明にはしない。

1. 任意のアバターを登録でき、登録済み対象を一覧とドロップのどちらからも指定できる。同名の2体を別の対象として扱い、未登録のルートを拒否する。

5. 同じ材質の参照を重複書き込みせず、登録時の外部共有先を含む影響先を隠さない。不完全な登録では反映させず、構成変更後の再登録が必要なことを表示する。
6. 不正な対象、参照変更、値の競合、書き込み拒否でプレビューと復元が意図しない上書きをしない。成功した例も確認し、部分失敗を全件成功や復元完了と表示しない。
7. 通常・狭幅・広幅、長い名前、共有先が多い行、一覧の先頭と末尾で読めて操作できる。実際の前面・背面画像を確認する。背景の透けと背面の消失も確認する。
8. 操作確認、二人での操作、保存・再読み込み、再適用の収束はそれぞれ区別して記録する。未実施の項目を検証済みと報告しない。

テストは親リポジトリの採用基準に従う。対象の取り違え、不正入力の誤反映、復元記録の消失、共有材の扱い、値の保持、プレビュー・復元の競合、失敗を成功とする誤表示は S として、実処理の入力・出力を検証する。文書・配色・固定されたファイル一覧を写すテストは追加しない。構文・参照・ビルドはツールの実行で、見た目と実入力は撮影・手動操作で確認する。
